The team built a candidate, but missed the handoff

Live music pilot on the configurable agent system · 29 October 2026

The autonomous research loop did not complete a scored experiment. It stopped at 40 model calls after three engineer assignments. The third engineer created seven candidate files, but the budget ended before submission and evaluation. We recovered those files unchanged for a separate diagnostic score: parsing improved, musical error did not.

What we asked the team to do

Turn seven supplied score excerpts into editable kern files with melody and chord symbols, compare the first candidate with the baseline, and use those measurements to refine or change the next attempt. The model was gpt-6.1-sol, with low reasoning effort for the lead and high for engineers. These were live decisions, not the scripted sorting test.

The team received seven anonymized images and fourteen prediction/export artifacts. Reference labels stayed with the protected evaluator. A ready Python/notation/OCR image was reused; no environment-engineer model call was needed. The overall allowance was 40 calls, 30 minutes and six assignments. Each engineer also had a 16-step, ten-minute limit. Full goal completion still requires 32 samples and the existing review/acceptance checks.

First, our interface got in the way

The first attempt used ten calls before we interrupted it. The documented default directory listing, ., was rejected. Input names did not explain their inputs/ prefix, and delegation descriptions omitted required field types. We preserved that attempt, fixed root listing and the descriptions/context, added regression tests, and restarted from fresh state. The first attempt is not counted as part of the retry's 40-call budget.

The first engineer inspected, then ran out of budget

The lead requested structural/conversion repair, preservation of available melody, and source-supported chord recovery. It correctly supplied the needed artifacts. The engineer inspected notation, raw MusicXML and images, but repeatedly returned to reading the brief and source details. It authored no reproducible candidate. Two model calls timed out at 180 seconds.

On its final step it tried to return an honest failure explanation with an empty file list. The tool rejected that because successful submission requires files. The lead therefore received a validation error and an empty artifact list, while the useful explanation remained buried in the action record. This is a failure-reporting defect, not missing reference labels.

The recovery engineer received an empty workplace

The lead then asked another engineer to recover and submit the earlier work, or rebuild it from the supplied inputs. But it supplied no inputs and the first engineer had produced no frozen artifacts. The recovery engineer checked the empty workspace and stopped after three calls with a specific request for source data. It did not invent notes or claim a result.

The lead used that observation to correct the next assignment. This demonstrates a response to execution evidence, but no measured recognition result had yet informed a research decision.

The third engineer finally implemented the candidate

The lead explicitly mapped the original sources into a third assignment. Some destination names included an extra input-directory prefix, so the engineer first had to discover a nested input location. It then inspected the artifacts and images, probed parsing, and implemented the candidate on its thirteenth action.

The candidate preserved supplied notation for three excerpts, used converter21 serialization for three malformed excerpts, and repaired zero divisions in the last MusicXML export using its explicit half-note types. It added no new visually inferred chords. It generated a build script, tests, provenance records, seven kern files and a report. Local checks claimed seven parseable files and transposition round trips.

Its next action inspected those artifacts in preparation for submission. At that point the shared 40-call budget was exhausted. Neither the engineer's finish call nor the lead's evaluation call could occur. Because the code had been authored through shell commands, the failure snapshot—which only tracks files written through the write-file tool—was empty. The candidate survived only in the workspace until we recovered it.

Lower error counts are better. Melody error remained 77.7%; chord error remained 100%. Parsing improved by two samples. The evaluator still rejected two melody files, and source-style chord labels such as G major/B did not satisfy the required G:maj/B dialect. The worker's local converter21 checks therefore did not establish compatibility with the protected reader.

The historical enlarged-Audiveris engine result was 87/130 melody errors and 30/38 chord errors, but that evaluated different output artifacts. It is context, not the direct before/after comparison above. The directly scored supplied kern set includes six kern files; the remaining sample has MusicXML but no supplied kern, so it counts as missing in this comparison.

The distinction matters: the diagnostic score was produced by us after freezing the unchanged workspace files. The team itself recorded zero evaluations and never chose a next experiment from these musical measurements. Its state remains unchanged and the goal remains unmet.

What passed, and what needs to change

The configured roles ran through one runtime, Docker executed real work, prepared dependencies were reused, labels remained protected, and budgets stopped the run. All saved integrity checks passed. The run lasted 17.7 active minutes and has 38 completed model receipts out of 40 attempted/reserved calls. The initial interrupted attempt adds 10 calls and about 3.5 minutes. Complete timeout token usage and dollar cost are unavailable.

  • Make handoffs verifiable. Use stable artifact IDs and explicit destination rules. A rebuild assignment must not start with no source inputs and no parent artifacts.
  • Preserve progress and failures. Maintain a compact public progress record, capture useful failure reports without requiring successful artifacts, and preserve declared outputs created through shell commands.
  • Reserve the final handoff. Make the shared remaining call budget visible and reserve room for submission, protected evaluation and the lead's next decision.
  • Provide a label-free format validator. Engineers need to test their files against the same syntax/reader contract used by the protected evaluator, without seeing reference answers.

Repeated inspection may be worsened by retaining only six recent actions without a durable findings summary. That is a plausible contributor, not a controlled causal result. The next step should be a small end-to-end pilot that reliably reaches submission and evaluation before increasing research breadth.
